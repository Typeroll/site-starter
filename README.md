# Typeroll CMS site starter

Your project's workspace for building or migrating a website with an AI agent.
Keep your brief, rules, SEO strategy, decisions and review evidence here.
Typeroll CMS stores the actual pages, blocks, templates and settings.

## Create your own project

1. On [Typeroll/site-starter](https://github.com/Typeroll/site-starter), choose
   **Use this template → Create a new repository**.
2. Select your GitHub account or organization and a project name. Choose
   **Private** for client work, business plans or unpublished research. Copy only
   the default branch. This creates an independent repository with fresh history;
   you do not need to fork the template.
3. Clone **your new repository**, using its **Code** menu, into the environment
   where your agent works. For example, replace `YOUR-OWNER` and `YOUR-SITE`:

   ```sh
   git clone https://github.com/YOUR-OWNER/YOUR-SITE.git
   cd YOUR-SITE
   ```

   You can also open your repository in a GitHub Codespace or connect it to an
   agent's cloud environment. The project is not tied to one computer. The
   included Markdown files need no installation; optional CLI commands need
   Node.js 20 or later.
4. Open the project in your agent and have it read `AGENTS.md`. If you need
   guidance, it starts or resumes `workflows/interview.md`. Otherwise use the
   kickoff in `workflows/new-site.md` or `workflows/migration.md`.
5. Connect Typeroll MCP, select the correct Organization, Site and Version,
   and record their IDs in `typeroll.json`. Planning can start before connecting.
   [Connection and workspace guide](https://typeroll.com/docs/getting-started/agent-workspace/).

The interview records **preserve or renew separately for text and for design,
including images**. You can keep every word while refreshing the design.
Your agent saves answers and the next question in `brief/interview.md` so another
session can continue without starting over. Prompts live in `workflows/`.

This is your **planning workspace**, not Typeroll's generated publication
repository. Do not edit exported build source to change your website. GitHub
repository creation does not create a Typeroll account, Site, hosting connection
or deployment. Self-hosted Typeroll uses its own portal's MCP endpoint.

## Keep your project current

```sh
npx @typeroll/mcp-server@latest init . --update
```

Review and commit the changes. Edited files, owner rules, interview answers and
`typeroll.json` are preserved; the updater reports files needing manual review.
This GitHub introduction makes `README.md` project-owned, so it is deliberately
preserved too. No upstream merge or re-cloning is needed.

Never commit API keys, passwords, cookies, private exports or local MCP client
configuration. Use OAuth or your agent's private credential settings. Client
configurations with local paths should be regenerated after cloning or moving.

## How this template stays synchronized

All project instructions and prompts below are generated by the released
`@typeroll/mcp-server` package, using the same source as `typeroll init`.
The original template checks for a verified stable release daily and supports
manual synchronization. It does not track unreleased Core changes. This GitHub
introduction and template maintenance files are the only additions.

The maintenance workflows run **only in `Typeroll/site-starter`**. They cannot
update your copy automatically; you decide when to run `init --update`. You may
delete `.github/` in your own repository. No special repository secret is needed.

# Website workspace

Keep project intent here; edit the website through Typeroll CMS.

1. Read AGENTS.md. For guidance, ask your agent to start or resume workflows/interview.md. Otherwise use workflows/new-site.md or workflows/migration.md. Save confirmed goals, rules and SEO strategy in brief/; record text and design/image choices separately for migrations.
2. Connect hosted MCP at https://app.typeroll.com/api/mcp?tools=compact.
3. Use an Organization key to create a site, or select an existing one.
4. Record its IDs and working version in typeroll.json. No secrets belong there.
5. Run npx @typeroll/mcp-server doctor . (inject TYPEROLL_API_KEY privately).

Start guide: https://typeroll.com/docs/getting-started/agent-workspace/

Update the generated scaffold with npx @typeroll/mcp-server init . --update.
Edited files are preserved and reported for manual reconciliation. Optional local
recipes: init . --recipes. They are reference Markdown, not automatically loaded.
